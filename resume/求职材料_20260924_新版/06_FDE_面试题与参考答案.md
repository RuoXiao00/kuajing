## 一 岗位理解与需求转化

### 01 FDE面试如何自我介绍

**参考回答：** 我叫黄健鸿，是仲恺农业工程学院计算机本科生，预计 2028 年毕业，想申请广州的 FDE 实习。我独立开发、部署并维护了跨境阁，把知识库问答、商品资料推荐和图片工作流做成在线应用。除了 Python、FastAPI 和 React 开发，我也实际处理了 Docker、Nginx、HTTPS、持久化与网络排查。现阶段没有客户交付经历，但愿意从环境验证、接口联调和交付文档做起，逐步承担需求澄清与现场问题闭环。可随时到岗、每周五天，并接受出差驻场。

**追问：** 你最有说服力的证据？选一条完整部署链路和一次可解释的故障，不用“沟通能力强”替代事实。

### 02 FDE与后端工程师售前和运维的区别

**参考回答：** 我理解 FDE 的核心是深入具体使用场景，把平台能力和客户现有系统结合，完成可验证的结果。它需要能写代码，也需要澄清需求、处理现场约束，并把共性问题反馈到产品。与后端相比更靠近使用现场；与售前相比通常更深入可运行实现；与运维相比还要关注业务流程和系统集成。但职责边界因公司不同，我会先确认岗位实际期待，而不是凭职位名称推断。

**追问：** 是否只要会部署Docker？不够，还要能解释为什么要做、和谁确认、怎么验收，以及失败时如何沟通。

### 03 只有个人项目凭什么申请FDE

**参考回答：** 我的经历还不能替代企业交付经验，但个人项目覆盖了从需求取舍、接口实现到实际部署维护的一条完整路径。我能提供代码、在线页面和部署说明，也经历过本地能运行、云端却失败的问题。能够证明的是学习、集成和排错能力；客户访谈、合同范围和复杂组织协调是我需要补的部分。我会从边界明确的实习任务开始，用可复现结果和文档建立信任，不把个人需求迭代说成服务过客户。

**追问：** 没做过的问题怎么回答？先承认，再给假设、验证步骤和升级协作方式。

### 04 客户说要一个AI助手你先问什么

**参考回答：** 我先找目标用户和具体任务：现在谁在做、一次要多久、最常卡在哪里、错误后果是什么。然后确认输入数据在哪里、能否授权使用、输出给谁、是否要写回业务系统。接着把模糊目标变成两三个可观察流程，例如查制度并给出处，而不是笼统的“什么都能问”。同时确认预算、期限、部署边界、业务验收人和 IT 对接人。需求记录要写明第一版包含和不包含什么，请双方确认后再实现。

**追问：** 客户不知道怎么定义？让他现场演示一次当前流程，用真实样例梳理，而不是丢一份技术问卷让他自己填。

### 05 客户所有需求都应该用大模型吗

**参考回答：** 不应该。精确查库存、计算价格或变更权限，应优先使用确定的数据库和业务接口；大模型可以帮助理解自然语言或组织解释，但最终数据与操作必须由可靠系统执行。文档问答适合尝试 RAG，而规则固定的审批不一定需要自主 Agent。我会比较收益、失败风险和维护成本，选择能满足需求的最简单方案。跨境阁里的价格过滤和任务状态就不该由模型自由决定。

**追问：** 客户坚持一定要Agent？先确认他要的是自主规划还是自然语言入口，用对照演示解释差异和成本。

### 06 怎么定义可以签字的验收标准

**参考回答：** 我会把验收拆成业务结果、技术约束和运维可交接性。比如知识助手，需要约定问题集、可回答与拒答范围、引用是否支持结论；同时约定并发条件下的延迟口径、错误处理、权限隔离和数据保留。每项都明确样本、环境、执行人和判定方式。指标不能只有“效果良好”，也不能只有容器健康。具体数字要经过基线测试和业务风险讨论后确定，我不会现场随口承诺95%准确率。

**追问：** 客户拿未见过的问题验收？应保留独立验收集，并约定范围外问题的处理，不能只背演示题。

### 07 两周POC应该怎么安排

**参考回答：** 前两天确认一个高价值流程、资料权限和验收样本，先打通最小接口。接下来完成基础检索和页面闭环，同时记录错误与耗时；中期给业务方看可运行版本，尽早暴露数据缺口。最后几天集中修复、做约定问题集测试、整理部署与回退步骤，并交付效果与限制报告。POC 的结果可以是继续、缩小范围或停止，不必为了证明项目成功而隐瞒不可行因素。这是我的规划方法，不是已做过的客户案例。

**追问：** 第一周就接不到客户数据怎么办？用经批准的脱敏样例验证接口，但明确它不代表真实业务效果。

### 08 客户临时增加需求怎么处理

**参考回答：** 我先问新增需求解决的业务问题，再评估它是否影响原有验收、数据权限和时间。如果是阻塞主流程的问题，和负责人确认优先级；如果是独立增强，记录影响和替代方案，选择推迟、交换范围或调整排期。沟通中给出可选结果和代价，避免简单说“做不了”，也不能默默接受后再延期。个人项目中我做过功能取舍，但没有合同变更经验，实际项目会遵守团队的变更流程。

**追问：** 谁决定？业务与交付负责人确认范围，工程师提供影响评估，不自行承诺商务条件。

## 二 部署与网络排查

### 09 在白板上解释跨境阁部署

**参考回答：** 浏览器先访问 GitHub Pages 的前端页面，再通过 HTTPS 请求 API 子域。域名解析到 ECS，Nginx 在宿主机接收请求，反向代理到 127.0.0.1:18000，Docker 将它映射到容器内的 FastAPI 8000。应用连接外部模型和数据源，业务文件保存在宿主机挂载目录。这样前端静态发布和后端运行分开，API 容器无需直接向公网暴露端口。当前方案简单适合个人项目，但不是跨可用区高可用架构。

**追问：** GitHub Pages能直接执行Python吗？它托管的是静态产物，后端要运行在独立服务中。

### 10 从输入域名到看到页面发生什么

**参考回答：** 客户端先得到 DNS 解析结果，随后建立网络连接，HTTPS 还需要 TLS 握手和证书验证，然后发送 HTTP 请求。服务器或代理路由请求，返回静态资源或 API 结果；浏览器解析并可能继续请求脚本、样式和后端接口。排错时按这些层次拆开，域名解析正确不等于端口可连，TLS 成功也不等于业务接口成功。前端出现问题时，我会看实际请求的地址、状态和响应内容，而不是只看页面一句“网络错误”。

**追问：** 缓存为什么让修改像没生效？DNS、浏览器静态资源和应用数据缓存位置不同，要确认请求版本与响应头再判断。

### 11 HTTP以前能用为何HTTPS页面连不上HTTP后端

**参考回答：** HTTPS 页面请求不安全的 HTTP 接口可能受到浏览器混合内容限制；这是协议与浏览器安全规则问题，和接口是否在服务器本机可用不是一回事。正确做法是为 API 配置可验证的 HTTPS，再配置准确的前端来源。域名实名、证书、接入备案和 CORS 也各自解决不同问题，我不会把“某次能访问”当成这些要求全部完成的证据。具体接入要求应以当前服务商和部署地区规则为准。

**追问：** 能否让所有用户关闭浏览器安全？不能作为交付方案，应修正服务端入口和配置。

### 12 线上打不开你如何分层定位

**参考回答：** 先确认影响范围和出现时间，再由内到外验证：容器是否运行、应用本机接口是否响应、宿主机端口是否监听、Nginx 是否转发、域名和 TLS 是否正常，最后看外网访问及浏览器控制台。每步保留证据而不是一次改多个配置。本机通而公网超时，优先看监听地址、系统防火墙、云安全组和网络；API通而浏览器失败，再看 CORS、Cookie 与前端配置。这样能把故障范围逐渐缩小。

**追问：** ping不通是否说明服务不可用？不一定，ICMP 可能被禁，应测试实际 TCP 端口和 HTTP 请求。

### 13 证书申请超时怎么排查

**参考回答：** 我实际遇到过 HTTP 验证超时。先确认验证域名解析到了目标服务器，本机带 Host 请求能得到 Nginx 响应，再检查公网验证所需端口的安全组和防火墙规则，以及挑战路径是否被错误代理。超时和返回404不是同一个问题：前者偏连通，后者偏路径或站点配置。解决后还要从外部验证证书和续期条件，不只看面板显示“已部署”。证书私钥不会放进截图或公共仓库。

**追问：** Nginx监听80就一定能签发吗？不一定，公网到该端口的路径和挑战内容都要可达。

### 14 容器中的localhost为什么容易出错

**参考回答：** localhost 指当前网络命名空间。容器里访问 127.0.0.1 是容器本身，不能想当然地访问宿主机另一个服务；Compose 同网络的服务通常用服务名和容器端口连接。跨境阁 Nginx 在宿主机，所以它访问宿主机的 127.0.0.1:18000，再由端口映射进入容器。如果以后把 Nginx 也容器化，就必须重新核对网络和目标地址。部署文件里的地址不能脱离组件所在位置解释。

**追问：** 为什么不用容器IP写死？容器重建后地址可能变化，服务发现应依赖稳定名称。[Docker 网络说明](https://docs.docker.com/compose/how-tos/networking/)

### 15 显示healthy是否代表所有功能正常

**参考回答：** 不代表。项目的健康检查访问根路径，可以发现应用没有起来等基础问题，但模型额度、知识库检索质量、Amazon 可访问性或图片保存权限出错时，根路径仍可能成功。我会区分存活、就绪和业务探测：存活检查保持轻量，就绪检查必要依赖，业务探测定期验证关键链路并控制成本。不能每几十秒做一次付费图片生成。Compose 启动依赖也需要明确健康条件，运行状态并不天然等于就绪。[Docker 启动顺序文档](https://docs.docker.com/compose/how-tos/startup-order/)

**追问：** 全部外部服务一失败就重启有用吗？可能扩大故障，应区分本进程损坏与上游不可用。

### 16 Docker构建下载很慢怎么处理

**参考回答：** 我先定位卡在镜像元数据、系统包、Python 依赖还是浏览器组件，而不是重复完整构建。连接超时与下载慢可能原因不同，要查看 DNS、出站网络、源可用性和缓存。可使用经过信任核验的镜像或软件源，固定版本并利用分层缓存；条件允许时在可靠的构建环境生成镜像，再传到服务器。不能为了快就关闭 TLS 校验或使用未知镜像。项目里我有这类排查经历，但不会把某个镜像地址说成长期保证可用。

**追问：** Docker缓存为什么失效？检查改变的构建层与 COPY 顺序，依赖清单应尽可能与频繁改动的业务文件分开。

### 17 容器重建后数据为什么还能保留

**参考回答：** 因为需要长期保存的数据放在宿主机挂载目录或持久卷，而不是只放在容器可写层。项目为知识库、推荐、商品和图片分别挂载目录，重建 API 容器不等于删除这些数据。但挂载不是备份，磁盘损坏、误删或错误迁移仍会丢失。交付时要记录数据位置、权限、容量和备份方法，并实际恢复一次。执行清理命令前应确认目标，不使用全局清理卷来解决项目空间问题。

**追问：** 能直接复制运行中的SQLite主文件吗？不应假设一致；可用备份 API 或在受控停写后复制，WAL 情况更要注意一致性。

### 18 旧知识库如何迁移到新服务器

**参考回答：** 先确认版本、目录、向量模型和业务元数据格式，选择停写备份或应用支持的一致性导出方式。传输后检查文件清单与校验和，设置运行用户权限，再确认文档数与片段数。最后用实际问题验证检索、来源和答案，数量一致不代表索引兼容。更换 Embedding 模型时应建立新索引，不能混用向量。原始资料和旧备份在迁移验收完成前保留，明确回退方案。

**追问：** 文档数相同却答错？比较模型版本、分块规则、集合名称、权限过滤及查询配置，继续看实际召回片段。

### 19 上线失败怎么回滚

**参考回答：** 发布前保存可识别的镜像版本、配置版本和数据备份，定义回滚触发条件。只回退代码可能不足，如果新版本改变了数据库结构，要确认旧版本还能读取，必要时采用先兼容再迁移的步骤。出现问题先判断是否可以停写或降级，再回到已验证版本并做业务验证。当前项目有部署资料和快照，但我不会声称已做过企业级蓝绿发布；如果团队使用发布平台，我会按平台的审批和回滚流程执行。

**追问：** 回滚等于恢复备份吗？不是，恢复旧数据会丢失期间新写入，必须单独评估。

### 20 为什么传了Python命令容器却启动了Web服务

**参考回答：** 先检查镜像 ENTRYPOINT 与 CMD，以及 Compose 是否覆盖 command 或 entrypoint。运行时追加参数通常是替换 CMD 或交给入口程序，不一定替换入口本身；如果入口脚本没有正确转发参数，就可能仍启动默认 Web 服务。我遇到这类现象时会先看实际进程与容器配置，确认临时任务没有误接到服务启动流程，再使用明确的入口运行一次性命令。密码输入应走受控交互，不把明文写进命令历史。

**追问：** 为什么不立即删除镜像重装？这是启动语义问题，先拿配置证据，重装可能无助且浪费时间。

## 三 AI集成与交付质量

### 21 Amazon取不到数据是不是备案问题

**参考回答：** 不能直接这样判断。备案或接入问题主要涉及用户访问部署站点的入口，而采集是服务器访问外部网站的出站请求。我要分别验证自己的 API 是否可达，以及服务器访问 Amazon 的响应状态、最终域名、正文结构和商品卡片数量。HTTP200 也可能是验证码或提示页。日志不足时只能说尚未定位，不能说一定是备案或一定是代码。针对解析变化可修复代码，针对访问限制则要降级或选授权资料渠道，不承诺无限重试可以解决。

**追问：** 页面显示历史商品算故障吗？如果明确标注生成时间和更新状态，是可用性降级；若伪装成最新数据，就形成误导。

### 22 客户演示时采集失败你怎么说

**参考回答：** 我会先说明目前哪个流程受影响、已有数据是否可用，并展示可验证的部分。例如：“当前上游采集没有返回可用商品，页面保留的是上次成功结果，时间显示在这里。我正在确认是网络访问还是页面结构变化，下一次进度更新时间是十分钟后。”不会把预置样例冒充实时结果，也不会没有依据就责怪供应商。演示前准备的脱敏样例可以使用，但必须说明用途和来源。

**追问：** 领导要求装作没出错？我会坚持明确数据状态，同时尽快给出不误导的替代演示路径。

### 23 接入第三方模型要核对哪些契约

**参考回答：** 我会列清鉴权方式、模型与接口版本、请求和响应结构、超时、限流、错误码、流事件以及计费相关操作。图片还要核对上传方式、文件类型、返回链接有效期和下载限制。把供应商差异封装在适配层，对外提供稳定业务错误，避免原始响应泄露凭据。跨境阁的 Coze 接入按生成类型映射工作流参数，产品图必需、提示词可选；已生成的图片还需要服务端保存才能减少临时链接过期影响。

**追问：** 返回格式变了怎么办？用真实脱敏响应做契约回归，验证版本，再发布适配；不要把所有异常都吞成空结果。

### 24 提示词RAG和微调怎么向客户解释

**参考回答：** 我会用任务说明：提示词像明确工作要求；RAG 在回答前查指定资料，适合文档更新和需要来源的场景；微调通过训练样本调整模型的行为，成本与准备要求更高。先确认问题出在知识缺失、检索错误还是输出方式，不能一上来推荐最复杂方案。我的项目实践主要是提示、RAG 和 API 集成，没有真实微调训练经历。向客户解释时重点是他的问题怎么解决、如何验证，而不是列框架名。

**追问：** 客户说必须100%准确？先限定高风险环节使用确定校验或人工确认，明确评测范围，不做无法兑现的承诺。

### 25 客户说问答不准怎样组织改进

**参考回答：** 请业务方提供具体错误问题、正确结论和依据，再区分资料不存在、资料过期、解析丢失、检索没命中、排序错误或生成不忠实。项目目前有空资料分支与引用，但没有校准过的充分证据阈值，不能据此宣称零幻觉。我会建立一个小的固定回归集，单因素调整，再给出哪些问题改善、哪些仍未解决。验收同时看错误率、拒答和延迟，不以一次演示成功证明全部问题解决。

**追问：** 用模型打分行吗？可辅助，但高风险和争议样例要有人工复核与清晰评分标准。

### 26 图片生成为什么要异步任务

**参考回答：** 图片生成和下载可能较久，保持一个长请求会让刷新、断网和超时更难处理。任务接口先返回标识，后台更新阶段和结果，前端查询状态；请求标识用于避免重复提交。当前项目使用本地工作线程与 SQLite，适合当前单实例，并非分布式队列。重启会把未完成任务标记中断，而不是自动重复触发付费生成。若增长到多个实例，再引入共享队列、任务租约和供应商结果对账。

**追问：** 供应商生成成功但下载失败？只重试保存，不能直接再生成；这是费用和一致性问题。

### 27 客户不允许数据离开内网怎么办

**参考回答：** 先确认哪些数据不能外发、能否脱敏、哪些系统必须隔离，以及模型服务是否已有批准的部署方式。完全不能出网时，现有云端 API 不能直接满足要求；需要选择客户批准的本地或专有环境模型，并重新评估算力、效果、运维与授权成本。依赖包、容器镜像和更新也要有受控导入渠道。我没有实际离线私有化交付经验，会和安全及基础设施同事核对方案，不承诺把公网项目原样搬进去就能运行。

**追问：** 只把文档转成Embedding就能外发吗？不能这样假设，向量仍可能涉及敏感信息，政策要覆盖数据处理链路。

### 28 上线前怎样处理密钥权限和提示注入

**参考回答：** 密钥只在后端受控配置中使用，不放前端构建变量或仓库；按环境和用途分权限，日志脱敏，发生泄露后撤销并轮换。上传接口与管理操作需要鉴权，对象下载需要检查归属。检索资料中也可能有恶意指令，所以工具执行必须在服务端校验权限和参数，不能相信模型的判断。CORS 只是浏览器机制，不替代身份认证。这些措施是多层防护，不是“提示词里写安全”就完成安全交付。[OWASP 提示注入](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

**追问：** 隐藏管理员页面地址能防护吗？不能，必须保护接口本身。

### 29 只有一台小服务器怎么做容量规划

**参考回答：** 先列资源消耗：浏览器采集占内存，文档解析和向量化消耗 CPU 或外部额度，模型等待占连接，图片占磁盘。用代表性负载测每阶段耗时、内存峰值与队列长度，再限制并发和上传大小。不能只用“2核2G”推导支持多少用户。增加 worker 也未必更好，当前调度与本地锁存在单实例假设，必须先改状态协调。若瓶颈在外部限流，加服务器可能没有收益。

**追问：** 第一个降级动作？停止高成本非关键任务或限流排队，保护核心读取和已保存结果，具体取决于观测证据。

### 30 怎样估算一个AI功能的成本

**参考回答：** 我会把模型调用、Embedding、精排、图片生成、计算、存储与网络分项估算。对问答用每次输入输出规模、每个流程调用次数和请求量计算，并计入重试；图片则按实际供应商计费单位。先用小样本测平均与高分位需求，再按低中高使用量给区间。成本和效果一起讨论，例如减少无必要的改写、控制输出、增量入库或缓存。当前没有商业运营数据，所以所有估算都标明假设，不能写成已节省多少钱。

**追问：** 缓存能否所有人共用？要看权限、知识版本和数据敏感度，跨用户缓存不当可能泄露内容。

## 四 协作事故与交付方法

### 31 线上故障如何先稳住再修复

## 五 基础与现场练习

### 37 解释常见HTTP状态和请求重试边界

**参考回答：** 401通常是缺少或无效认证，403偏权限拒绝，404是目标不存在或被隐藏；429表示限制请求，502常见于代理无法得到正常上游响应，504表示等待上游超时。代码只能帮助分类，还要看是谁返回的、正文和关联日志。GET 通常适合受限重试，付费 POST 不能只看超时就再次执行，因为服务器可能已经成功。CORS 报错也不是一个独立的服务器业务状态码，需要浏览器侧证据。

**追问：** TCP已建立为何还是慢？可能卡在TLS、代理、应用排队、外部模型或下载，需要分阶段计时。

### 39 接口集成编码与SQL题

**题目A：** 客户接口返回产品列表，有缺失字段、字符串价格和重复ID。写一个适配函数，只保留 ID 非空、价格为正有限数的记录，稳定保留第一条有效记录；输出不泄露原始响应中的其他字段。

```python
from decimal import Decimal, InvalidOperation

def normalize_products(rows):
    seen, result = set(), []
    for row in rows:
        if not isinstance(row, dict):
            continue
        raw_id = row.get("id")
        key = str(raw_id).strip() if raw_id is not None else ""
        raw = row.get("price")
        if not key or isinstance(raw, bool):
            continue
        try:
            price = Decimal(str(raw))
        except (InvalidOperation, ValueError):
            continue
        if not price.is_finite() or price <= 0 or key in seen:
            continue
        seen.add(key)
        result.append({"id": key, "price": str(price)})
    return result
```

**验收：** 空输入、无效后接有效、重复ID、NaN、Infinity和布尔价格；平均 O(n) 时间、O(n) 空间。金额已由契约说明币种，不自行猜符号和换算。这个函数是面试练习，不改项目代码。

**题目B：** 按租户统计过去24小时任务失败率，练习表为 tasks(tenant_id, status, created_at)，时间统一存储为UTC可比较值。

```sql
SELECT tenant_id,
       COUNT(*) AS total,
       SUM(CASE WHEN status = 'failed' THEN 1 ELSE 0 END) AS failed,
       1.0 * SUM(CASE WHEN status = 'failed' THEN 1 ELSE 0 END)
           / COUNT(*) AS failure_rate
FROM tasks
WHERE created_at >= :since_utc
GROUP BY tenant_id;
```

**追问与答案：** 分母是否应包含运行中？要先定义业务口径；若只统计完成结果，应筛成功和失败，但需同时报告积压，避免慢任务被隐藏。使用绑定参数，不拼接用户输入。没有记录的租户不会出现在这个结果里，要完整展示需要租户表左连接并处理零分母。

## 六 一次事故沟通的完整说法

**首次通知：** “当前图片生成后的保存环节出现异常，已保存的历史图片可以查看。我们暂时关闭重复生成入口，正在核对任务状态，避免重复调用。下一次更新在十分钟后。”只有在相应事实已核实后才这样说。

**进展通知：** “已确认生成服务返回了结果，问题发生在下载保存；正在对现有任务重试保存，不会主动重新发起生成。仍有部分链接需要核验有效期。”不要在不能保证的情况下说一定不产生额外费用。

**恢复通知：** “保存功能已恢复，已核对本次受影响任务的结果。无法补存的任务会单独标明；如需重新生成，会作为新操作处理。我们将补充保存失败的告警和回归用例。”

**复盘结构：** 影响范围 → 触发条件 → 根因与证据 → 临时恢复 → 防复发措施 → 负责人和验证日期。不要把“加强意识”当作唯一行动项。
